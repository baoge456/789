自编【Pi节点云服搭建】教程 (2026年·双方案完整版)

📌 写在前面

本教程面向希望在 Windows 电脑上运行 Pi Node，并通过 云服务器 (VPS) 进行端口转发以提升网络连通性的用户。

重要变化（2026年）： Pi Network 已于2025年2月20日启动开放主网。当前节点运行奖励与网络稳定性直接挂钩，对节点在线率和端口开放要求更高。

本教程提供两种经过验证的方案，您可以根据需要选择：

  • 方案一（经典）：OpenVPN + Gost — 稳定成熟，适合追求传统VPN方案的用户。
  • 方案二（现代）：Xray (karing) + FRP — 更轻量，性能更好，无VPN依赖，是目前推荐的方案。
⚠️ 风险提示： 运行节点需要一定的技术基础，涉及服务器配置、网络安全等。请自行评估风险，并保管好你的 Pi 账户与节点私钥。本教程仅供参考，不构成投资建议。

一、节点电脑配置检查

Pi Node 基于 Docker 运行，需要 Windows 系统支持虚拟化及 WSL2 / Hyper-V。

  1. 检查系统版本： 按 Win+R，输入 winver，确保系统为 Windows 10 22H2 或 Windows 11 以上版本。
  2. 启用虚拟化：
    • 打开任务管理器 → 性能 → 确认"虚拟化"已启用。
    • 进入"控制面板" → "程序" → "启用或关闭 Windows 功能"。
    • 勾选以下三项：
      ✅ 适用于 Linux 的 Windows 子系统 (WSL)
      ✅ 虚拟机平台 (Virtual Machine Platform)
      ✅ Hyper-V (如系统支持)
    • 点击"确定"，按提示重启电脑。
  3. 安装 WSL2 内核更新包： 下载并安装 wsl_update_x64.Msi。
  4. 设置 WSL2 为默认： 以管理员身份打开 PowerShell 或 CMD，执行：
    wsl --set-default-version 2
  5. 检查虚拟化支持： 以管理员身份运行 PowerShell，执行：
    dism.exe /online /get-features /format:table | findstr /c:"VirtualMachinePlatform"
  6. 在 Windows 功能中启用 Hyper-V： 控制面板 → 程序 → 启用或关闭 Windows 功能 → 勾选 Hyper-V。
  7. （可选）安装 Linux 发行版： 在 Microsoft Store 中搜索并安装 Ubuntu 22.04 LTS，用于后续调试。

🛡️ 通用关键配置：本地防火墙 & 方案切换原则 & 可用性率

以下配置和原则适用于两种方案，请务必在部署前完成。

1. 本地电脑防火墙：添加入站规则（必须）

即使云服务器和路由器端口都已开放，Windows 防火墙也可能阻止外部流量到达您的 Pi Node。您需要手动添加一条允许 31401-31403 端口入站的规则。

方法一：使用命令快速添加（推荐）

以管理员身份打开 PowerShell，执行以下命令：

netsh advfirewall firewall add rule name="Pi-Node-Inbound" dir=in action=allow protocol=TCP localport=31401-31403

验证规则是否生效：

netsh advfirewall firewall show rule name="Pi-Node-Inbound"

如果有规则详细信息输出，说明已添加成功。

方法二：通过图形界面添加

  1. 按 Win+R，输入 wf.msc，回车打开高级安全防火墙。
  2. 点击左侧 "入站规则" → 右侧 "新建规则…"。
  3. 规则类型：选择 "端口" → 下一步。
  4. 协议和端口：选择 "TCP"，选择 "特定本地端口"，输入 31401-31403 → 下一步。
  5. 操作：选择 "允许连接" → 下一步。
  6. 配置文件：全选（域、专用、公用）→ 下一步。
  7. 名称：输入 Pi-Node-Inbound → 完成。
💡 如果您使用第三方防火墙（如 360、火绒等），请在对应软件的"联网控制"或"端口设置"中放行 31401-31403 端口。

2. 方案切换核心原则

两种方案共享同一个云服务器和本地 Pi Node，它们的区别仅在于"网络隧道"和"端口转发工具"。

您使用的方案网络隧道工具端口转发工具
OpenVPN + GostOpenVPN（服务端+客户端）Gost
Xray + FRPXray（服务端 + karing客户端）FRP

切换的本质： 停止当前方案的工具，启动另一方案的工具，不需要修改 Pi Node 的任何配置。Gost 的配置文件（指向 10.8.0.2）在切换时无需修改，只需在 OpenVPN 方案下启动它，在 FRP 方案下停止它。

3. 关于"可用性率"（在线率）的恢复

切换方案或修复节点后，您可能会发现 PiCheck 等工具显示的"今天可用性"在几小时内仍是 0%。这是正常现象，因为：

  • 统计有延迟： 可用性率是滚动统计过去 1小时、24小时的在线数据。
  • 入站连接需"重新发现"： 网络需要时间（通常 24-48 小时）来重新将您的节点标记为稳定在线。

在修复后的 24 小时内，请重点关注这三个指标：

  • ✅ 核心端口 (31401-31403) 是否 OPEN（是 → 链路通）
  • ✅ Incoming connections 是否 > 0（是 → 正在被连接）
  • ✅ 本地健康检查：访问 http://127.0.0.1:31401/health 返回 {"database_connected":true,"core_up":true,"core_synced":true}（是 → 节点自身正常）
只要以上三个指标正常，可用性率会在 1-3 天内自然回升，无需反复重启或调整。

🔹 方案一：OpenVPN + Gost（经典稳定）

本方案通过 OpenVPN 在云服务器和本地电脑间建立虚拟局域网，由 Gost 完成端口转发。

4.1 安装 OpenVPN 服务端

wget https://git.io/vpn -O openvpn-install.sh && bash openvpn-install.sh

安装过程中按提示操作：

  • 协议选择 1 (UDP)
  • 端口默认 1194 或自定义
  • DNS 建议选 2 (Google)
  • 客户端名称回车默认即可

安装完成后，会在 /root/ 目录生成 client.ovpn 配置文件，下载到本地电脑备用。

4.2 安装并配置 Gost

使用一键脚本安装 Gost：

wget --no-check-certificate -O gost.sh https://raw.githubusercontent.com/KANIKIG/Multi-EasyGost/master/gost.sh && chmod +x gost.sh && ./gost.sh

在菜单中：

  • 选择 1 安装 Gost
  • 选择 7 新增转发配置
  • 类型选 不加密中转
  • 本地端口填 31401
  • 目的地地址填 10.8.0.2:31401（假设 OpenVPN 分配给本地电脑的 IP 是 10.8.0.2）
  • 重复以上步骤，添加 31402、31403 端口
💡 如果无法确定 OpenVPN 分配给本地电脑的虚拟 IP，可以在本地电脑连接 OpenVPN 后，通过 ipconfig 查看 Ethernet adapter OpenVPN TAP-Windows6 下的 IPv4 地址。
⚠️ Gost 配置中的目标地址必须与本地电脑在 OpenVPN 隧道中获得的虚拟 IP 一致。通常为 10.8.0.2。

4.3 本地电脑连接 OpenVPN

  1. 将云服务器生成的 client.ovpn 文件复制到本地电脑的 C:\Program Files\OpenVPN\config\ 目录。
  2. 以管理员身份运行 OpenVPN GUI，在系统托盘处右键选择"连接"。
  3. 连接成功后，记下虚拟 IP（通常为 10.8.0.2）。

4.4 在 Pi Node 中验证

  • 打开 Pi Node 软件，点击 "Check Now" 检测端口，31401-31403 应显示为 OPEN。
  • 点击 "Start Node" 启动节点，观察区块同步状态。
💡 如果端口检测仍显示 CLOSED，请检查本地防火墙规则： 在 PowerShell 中执行 netsh advfirewall firewall show rule name="Pi-Node-Inbound" 确认入站规则已添加并生效。

🔸 方案二：Xray (karing) + FRP（轻量现代）

本方案通过 Xray 代理（karing 客户端）打通网络隧道，由 FRP 完成端口转发，无 VPN 依赖，是当前推荐的方案。

5.1 云服务器：安装并配置 FRP 服务端 (frps)

cd ~ wget https://github.com/fatedier/frp/releases/download/v0.69.1/frp_0.69.1_linux_amd64.tar.gz tar -zxvf frp_0.69.1_linux_amd64.tar.gz cd frp_0.69.1_linux_amd64

编辑配置文件 frps.toml：

nano frps.toml

写入以下内容（端口和 token 可自定义）：

bindPort = 7000 auth.token = "your_secure_token_here"

将 frps 配置为 systemd 服务（开机自启）：

cat > /etc/systemd/system/frps.service << 'EOF' [Unit] Description=FRP Server After=network.target [Service] Type=simple WorkingDirectory=/root/frp_0.69.1_linux_amd64 ExecStart=/root/frp_0.69.1_linux_amd64/frps -c /root/frp_0.69.1_linux_amd64/frps.toml Restart=on-failure RestartSec=5 StandardOutput=journal StandardError=journal [Install] WantedBy=multi-user.target EOF systemctl daemon-reload systemctl start frps systemctl enable frps # 检查 frps 是否运行 ps aux | grep frps | grep -v grep # 检查端口是否监听 ss -tlnp | grep -E "7000|31401"

5.2 云服务器：安装并配置 Xray (s-ui 面板)

bash <(curl -Ls https://raw.githubusercontent.com/alireza0/s-ui/master/install.sh)

安装后：

  • 访问 http://你的服务器IP:2095/app/ 进入面板
  • 在"入站列表"中，添加一个 VLESS + Reality 协议的节点
  • 记下该节点的连接信息（地址、端口、UUID、流控等），供本地 karing 客户端使用

5.3 本地电脑：配置 karing (Xray 客户端)

  1. 打开 karing，在"订阅"或"节点"管理中，添加从 s-ui 面板获取的 VLESS 节点。
  2. 确保节点状态为"已连接"。
  3. 记下 karing 的本地 SOCKS5 代理端口（默认 3067，可在设置中查看）。

5.4 本地电脑：配置并运行 FRP 客户端 (frpc)

下载 Windows 版 FRP，解压到本地目录，如 D:\Edge浏览器\frp_0.69.1_windows_amd64。

创建 frpc.toml 配置文件，内容如下（替换 IP 和 token）：

serverAddr = "你的云服务器公网IP" serverPort = 7000 auth.token = "your_secure_token_here" [[proxies]] name = "pi_31401" type = "tcp" localIP = "127.0.0.1" localPort = 31401 remotePort = 31401 [[proxies]] name = "pi_31402" type = "tcp" localIP = "127.0.0.1" localPort = 31402 remotePort = 31402 [[proxies]] name = "pi_31403" type = "tcp" localIP = "127.0.0.1" localPort = 31403 remotePort = 31403

启动 frpc： 在 PowerShell 中进入 FRP 目录，执行 frpc -c frpc.toml，看到 start proxy success 即成功。

（可选）设置 frpc 开机自启：

  • 在 FRP 目录下创建 start_frpc.bat，写入：
    @echo off
    cd /d D:\Edge浏览器\frp_0.69.1_windows_amd64
    frpc -c frpc.toml
  • 按 Win + R，输入 shell:startup，将 start_frpc.bat 复制到打开的文件夹中。

5.5 在 Pi Node 中验证

  • 打开 Pi Node 软件，点击 "Check Now" 检测端口，31401-31403 应显示为 OPEN。
  • 观察 Incoming connections 数量，应逐渐从 0 开始增加。
  • 在云服务器上执行 curl http://127.0.0.1:31401/health，应返回 {"database_connected":true,"core_up":true,"core_synced":true}。
💡 如果端口检测仍显示 CLOSED，请检查本地防火墙规则： 在 PowerShell 中执行 netsh advfirewall firewall show rule name="Pi-Node-Inbound" 确认入站规则已添加并生效。

🔄 方案切换指南

两种方案可以共存于同一台云服务器和本地电脑，通过简单的服务启停即可切换。

切换前准备

  • 备份当前 Gost 配置文件（如果使用 OpenVPN 方案）：cp /etc/gost/config.json /etc/gost/config.json.openvpn.bak
  • 确保本地电脑已安装对应的客户端软件（OpenVPN GUI 或 karing）
  • 确认云服务器安全组已放行两种方案所需的所有端口

从 OpenVPN 切换到 Xray + FRP

  1. 本地电脑： 断开 OpenVPN，打开 karing 并连接 Xray 节点。
  2. 云服务器： 停止 Gost，启动 frps。
    # 停止 Gost cd ~ && ./gost.sh # 选择 5 停止 # 启动 frps systemctl start frps
  3. 本地电脑： 启动 frpc（双击 start_frpc.bat）。
  4. 验证： 在 Pi Node 中 Check Now，或在云服务器执行 curl http://127.0.0.1:31401/health。

从 Xray + FRP 切换回 OpenVPN

  1. 本地电脑： 断开 karing 的 Xray 连接，启动 OpenVPN GUI 连接。
  2. 本地电脑： 停止 frpc（按 Ctrl+C）。
  3. 云服务器： 停止 frps，启动 Gost。
    # 停止 frps systemctl stop frps # 启动 Gost cd ~ && ./gost.sh # 选择 4 启动
  4. 验证： 在 Pi Node 中 Check Now，或在云服务器执行 curl http://127.0.0.1:31401/health。
✅ 切换完成后，端口检测应显示 31401-31403 为 OPEN，Pi Node 状态为 Synced!。

❓ 常见问题

Q0：端口检测显示 CLOSED，但云服务器和路由器设置都正确？

  • 很可能是本地电脑防火墙拦截了入站连接。 请按"通用关键配置"章节中的步骤，在 Windows 高级安全防火墙中为 31401-31403 端口添加一条"允许连接"的入站规则。
  • 如果您使用第三方防火墙软件，请同样放行这些端口。

Q1：切换方案后，Pi Node 的 Incoming connections 为 0？

  • 检查云服务器上对应服务是否正常运行（Gost 或 frps）。
  • 检查本地客户端是否连接成功（OpenVPN 或 karing）。
  • 在云服务器上执行 curl http://127.0.0.1:31401/health，确认本地节点可访问。
  • 入站连接需要时间积累，等待 10-30 分钟观察。

Q2：frpc 报错 port unavailable？

  • 原因： 云服务器上 Gost 还在运行，占用了 31401-31403 端口。
  • 解决： 用 ./gost.sh 停止 Gost，再启动 frpc。

Q3：frpc 报错 connection refused？

  • 检查 1： 本地 karing 是否已开启并连接？SOCKS5 代理端口是否正确（默认 3067）？
  • 检查 2： 云服务器安全组是否放行了 7000 和 31400-31409 端口？
  • 检查 3： 云服务器上 frps 是否正在运行（ps aux | grep frps | grep -v grep）？

Q4：端口检测显示 31401-31403 OPEN，但 Incoming connections 依然为 0？

  • 端口开放只代表外部可以访问，入站连接需要其他节点主动连接你，需要时间积累。
  • 可用性率（在线率）需要 24-48 小时稳定运行才能恢复正常水平。

📦 s-ui 面板管理

s-ui 是一个轻量级 Xray 管理面板，可以方便地查看流量、管理节点。

  • 一键安装命令：
    bash <(curl -Ls https://raw.githubusercontent.com/alireza0/s-ui/master/install.sh)
  • 指定版本安装：
    VERSION=1.1.0 && bash <(curl -Ls https://raw.githubusercontent.com/alireza0/s-ui/$VERSION/install.sh) $VERSION
  • 安装成功后运行面板命令：s-ui
  • 默认访问地址：http://你的服务器IP:2095/app/

  • 建议选择版本 90~100 之间的稳定版本进行安装。

🌐 本地分流脚本 (Win平台)

如果你希望只让 Pi Node 走 VPN 通道，而其他国内网站直连，可以使用分流脚本。

  • 开源项目地址：https://github.com/lmc999/auto-add-routes
  • 下载打包文件：分流脚本包 (请自行核对安全性)
  • 将脚本解压至 OpenVPN 的 config 目录，并确保与 client.ovpn 同目录，重命名批处理文件以匹配配置文件名称。
⚠️ 注意： 一条宽带下运行多个节点时，不建议使用分流，以免造成网络冲突。
