🧩 Sun-Panel Helper 完整部署教程 Windows · 独立目录 · 不侵入原项目

📍 基于真实环境：原有 Sun-Panel 位于 D:\记事本\sunpanel ，Helper 独立部署在 D:\记事本\sunpanel-helper
🔗 联动核心：Helper 通过挂载原项目的 conf/custom 目录将组件注入 Sun-Panel，无需修改 Sun-Panel 任何原有文件。
🌐 访问入口：Sun-Panel → http://localhost:3002  |  Helper 管理端 → http://localhost:33002

📁 最终目录结构（部署完成后）

📂 D:\记事本\
├── 📁 sunpanel # 原 Sun-Panel 项目 (未做任何改动)
│ ├── 📁 conf/
│ │ ├── 📁 custom/ ← 关键桥梁 (Helper 写入组件, Sun-Panel 读取)
│ │ ├── 📁 database/
│ │ ├── 📁 uploads/
│ │ ├── 📄 conf.ini
│ │ └── 📄 conf.example.ini
│ ├── 📁 helper-data/ (可选，用于集中存放Helper额外数据)
│ ├── 📁 helper-backups/ (可选)
│ └── 📄 docker-compose.yml (原 Sun-Panel 编排，不动)
│
└── 📁 sunpanel-helper ✨ 新建独立目录（Helper 完整环境）
├── 📁 data/ # Helper 运行时数据库/状态
├── 📁 backups/ # Helper 备份文件
└── 📄 docker-compose.yml # Helper 服务配置
⚡ 部署前必读：原 Sun-Panel 项目中的 D:\记事本\sunpanel\conf\custom 目录必须存在。如果缺失，Helper 无法将组件注入 Sun-Panel。本教程会明确创建它。

⚙️ 第一阶段：准备原 Sun-Panel 项目中的关键目录

1 确保 custom 目录存在

Helper 与 Sun-Panel 通过 conf/custom 通信，该目录必须提前存在。

mkdir D:\记事本\sunpanel\conf\custom
# 验证目录是否创建成功
💡 若原 Sun-Panel 目录下没有 helper-data 或 helper-backups，可以顺便创建（非强制，但推荐统一管理）：

📦 第二阶段：建立 Helper 独立运行环境

2 创建 sunpanel-helper 及数据文件夹

Helper 的所有配置和数据都放在独立目录，与原项目隔离。

mkdir D:\记事本\sunpanel-helper & cd /d D:\记事本\sunpanel-helper & mkdir data backups
✅ 完成后目录结构：D:\记事本\sunpanel-helper\data 和 D:\记事本\sunpanel-helper\backups

🐳 第三阶段：编写 Helper 容器配置

3 在 D:\记事本\sunpanel-helper 中创建 docker-compose.yml

使用官方镜像 madrays/sun-panel-helper:latest，挂载原项目的 custom 目录（绝对路径）及自身数据目录。

📄 docker-compose.yml (完整正确版) 
version: '3'

services:
  sun-panel-helper:
    image: madrays/sun-panel-helper:latest
    container_name: sun-panel-helper
    environment:
      - BACKEND_PORT=3001
    ports:
      - "33002:80"               # 宿主机33002映射Helper前端
    volumes:
      # 绝对路径指向原 Sun-Panel 的 custom 目录（关键！）
      - D:/记事本/sunpanel/conf/custom:/app/backend/custom
      # Helper 自身数据目录（相对路径，位于当前目录下）
      - ./data:/app/backend/data
      - ./backups:/app/backend/backups
    restart: unless-stopped

⚠️ 注意：不要使用 build: .，直接拉取镜像；路径中反斜杠改为正斜杠 / 。保存时编码选择 UTF-8。

# 确保当前在 D:\记事本\sunpanel-helper 目录下

🚀 第四阶段：启动 Helper 服务

4 运行 docker-compose 并验证
docker-compose up -d
docker ps | findstr sun-panel-helper
docker-compose logs --tail=30
🌐 浏览器访问 http://localhost:33002 ，出现 Helper 登录界面即代表成功。默认账号 helper / 密码 helper123

🎨 第五阶段：在 Helper 内部署组件，Sun-Panel 中显示

5 让 Helper 组件出现在 Sun-Panel 页面

原 Sun-Panel 无需任何代码修改，只需通过 Helper 前端完成组件配置。

  • ✅ 登录 Helper (http://localhost:33002)
  • ✅ 左侧菜单 → 「组件市场」 → 选择任意组件（例如“时钟 / Hello World 测试”）
  • ✅ 编辑组件时，“Helper域名前缀” 必须填写 → http://localhost:33002 (末尾不要斜杠)
  • ✅ 点击 「应用到固定组件池」 或 「应用到自由组件池」
  • ✅ 进入「固定组件」或「自由组件」页面 → 将组件从左侧池子拖拽至右侧布局区域 → 点击右上角 「部署配置」
  • ✅ 刷新 Sun-Panel 页面 (http://localhost:3002) ，组件即显示在底部或自定义区域。
💡 自由组件需要在 Sun-Panel 开启编辑布局模式，从左侧组件库选择 Helper 提供的组件。固定组件会自动追加到页面底部。
🔁 原理：Helper 将生成的 HTML/CSS/JS 写入 D:\记事本\sunpanel\conf\custom 目录，Sun-Panel 启动时会自动读取该目录下的内容并渲染，因此原项目完全无侵入。

⚠️ 常见问题 & 路径关键点

🔸 Helper 部署后 Sun-Panel 无变化
→ 检查 D:\记事本\sunpanel\conf\custom 目录是否存在且 Helper 容器有写入权限。进入容器测试: docker exec -it sun-panel-helper ls /app/backend/custom 应该能看到 helper 生成的文件。
🔸 中文路径报错 (D:\记事本)
→ 新版 Docker Desktop 通常支持，若遇到挂载错误，可将整个项目迁移至英文目录 (如 D:\docker\sunpanel)，并同步修改 compose 中的 volumes 绝对路径。
🔸 端口 33002 已被占用
→ 修改 compose 文件中 "33002:80" 为其他端口，如 "33003:80"，并相应修改 Helper 域名前缀。
🔸 Helper 登录后提示后端连接失败
→ 检查 Helper 容器内部端口 3001 是否正常，重新部署时确保 environment 中 BACKEND_PORT=3001 未改动。

📌 关于「原 Sun-Panel 目录下增加目录」的补充
教程中明确：原 Sun-Panel 项目本身不需要新增任何强制目录，但为了让文件更整洁，你可以手动创建 helper-data 和 helper-backups （可选）。
真正必不可少的是 conf/custom 目录 —— 它必须存在，且已在步骤1中创建。Helper 容器不会修改原项目的其他任何文件，只向 custom 目录写入渲染内容。
